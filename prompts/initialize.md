# Initialize an independent Agent Hub Instance

Use this Agent Hub Core checkout to help me establish an independent Instance.
Follow Discover → Propose → Configure → Verify. Read README.md and
docs/getting-started.md before making changes.

First ask which existing project roots I authorize you to inspect, where the new
Instance should live, and whether it is personal or shared. Inspect only those
roots. Use `bin/hub discover --root ...` with Python 3.11+. Do not read arbitrary
private directories, credentials, user MCP configuration, or external context.

Propose repositories to attach or clone; verify origins and default branches.
Keep registered, available and visible distinct. Ask which work sources, context
locations, skills, MCP servers, tools and services should be referenced. Distinguish
executable or path presence from verified connectivity. Register Core itself for
self-hosting, separately from the pinned runtime checkout.

Present the Instance proposal before configuration. After approval, initialize it
with a pinned committed Core source, write portable hub.toml and repos.toml, keep
machine paths in ignored local.toml, and generate the VS Code workspace. Do not
copy context or scripts, install hooks on existing repos, or start services without
authorization. Offer optional personal overlay references for shared Instances.

Run diagnostics. Prepare one explicitly authorized bounded work unit and demonstrate
a Worker in isolated worktrees. Record actual verification and limitations. Provide
the Orchestrator launch and workspace paths. Do not create or push remote repos.

Repository discovery roots are Instance choices, never Core defaults. Keep any
personalized initialization prompt with the Instance rather than public Core.
